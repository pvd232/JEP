# Joint annotation and similarity pilot

This experiment checks whether both objectives train a shared encoder and whether the complete training and evaluation procedure runs through VIPER. Its passages and labels are generated by a script. They contain no JEP testimony or expert judgments.

The dataset covers reparations, harm, sanctions and restoration. Each passage binds an actor, an action or event, an outcome and an affected group. Full cases remain together in training, development or test data. Three combinations of outcome and affected group are reserved for test. Separate action and actor combinations supply development cases. Composed comparison questions occur in the test data only. Every atomic concept also appears during training. The composed test questions include full matches, partial matches and mismatches.

The numeric targets are a controlled kernel: `0.5 + 0.5 * fraction of matching attributes`. The training code uses `(1 + cosine) / 2` on unit vectors. This score construction makes orthogonal representations of distinct attribute values compatible with the target. These numbers are synthetic diagnostic targets, not judgments of semantic similarity by experts.

## Model and comparisons

A T5 encoder supplies contextual token states. Their mean is projected to a normalized passage embedding. The T5 decoder predicts the passage's typed record using those same encoder states. Annotation loss averages token cross-entropy within each answer, then across answers. Rating loss is MSE. Training minimizes `rating_mse + annotation_weight * annotation_ce`.

The ratings arm sets annotation weight to zero. The joint arm uses the true generated records. A third arm uses records reassigned between training cases. Arms share initialization, sampled training pairs, steps and optimizer settings. The initial gradient diagnostics verify that both objectives reach the shared encoder. Test annotations never enter training or prediction. Evaluation saves predictions, then recomputes MSE and Spearman correlation from that artifact.

`tiny` creates a small randomly initialized T5 with a training-only vocabulary. It is an offline implementation check. `pretrained` uses a pinned revision of `google/flan-t5-small` for the initial GPU pilot. Its results remain specific to this synthetic experiment. This is an adaptation of joint training, with a trainable encoder, and should be compared with a published CASE reproduction in the subsequent scientific experiment.

## Run

Use Python 3.11 or newer in a dedicated virtual environment. Install a CUDA-compatible PyTorch build on the GPU host, then:

```bash
python -m pip install -r pilot_requirements.txt
python -m jep_pilot.data
git add jep_pilot tests/test_joint_pilot.py pilot_requirements.txt viper.toml pilot_data PILOT.md
git commit -m "Add joint annotation and similarity diagnostic"
python -m jep_pilot.run --device cpu --mode tiny --steps 8
```

Before a pretrained run, resolve and record an immutable model revision, then pass it explicitly:

```bash
python -m jep_pilot.run --device cuda --mode pretrained --revision 0fc9ddf78a1e988dac52e2dac162b0ede4fd74ab --steps 120
```

Run the existing GCP L4 through its GitHub Actions route when the runner is available. The connected development host currently requires Google Cloud reauthentication to start the MANTRA machine. No GPU job has been submitted by this pilot setup.

The initial run uses one seed. A scientific comparison needs several seeds, expert-defined targets, and a fixed selection rule for the annotation weight using development data. Evidence for JEP transfer requires expert evaluation on testimony.
